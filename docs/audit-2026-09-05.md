# HeatMap: Show Desktop and reading reliability

Reviewed desktop/Peek transitions, sensor errors, background retries, and data
freshness. An independent agent reviewed the implementation again and added sensor
regressions. DLLs, the driver, launcher, elevation, and production autostart were
unchanged.

## Fixes

- The right edge of the taskbar no longer triggers Peek. Work areas, child windows
  of the primary/secondary taskbar, and the auto-hide shell surface are considered.
  With a right-side taskbar, the trigger sits directly to its left; internal
  boundaries between monitors remain excluded.
- The window receives `DWMWA_EXCLUDED_FROM_PEEK` so the system desktop preview
  does not make it transparent. Microsoft describes this attribute as protection
  from fading during Peek: [DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute).
- The independent fallback recovers from native minimization and maintains its
  position immediately in front of the desktop surface in Z-order. Visibility is
  checked every 250 ms, including with Peek OFF, without activation. Other windows
  are not moved. An application window in front of the desktop stays in front of
  the widget; a topmost predecessor does not make the widget topmost. This uses the
  documented [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)
  and [ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow).
- Returning to the desktop cancels active Peek and restores the saved position;
  focus remaining on the taskbar is accounted for. Old animation callbacks check
  their generation and do not move a window belonging to a new Peek session.
- An invalid numeric value from one sensor no longer discards valid readings from
  the same hardware block. `TypeError`, `ValueError`, and overflow are handled.
- A persistent hardware-block failure requests recovery through the existing
  cooldown. An error during the infrequent storage update remains active between
  cached samples; disk readings are temporarily hidden until an actual refresh.
  Failure of one disk conservatively hides the entire disk group; CPU/GPU updates
  continue.
- After 10 seconds without a new sample, the UI hides old readings, shows that it
  is waiting for fresh data, and stops updating peaks/alerts. Exactly 10 seconds
  is still acceptable; the two-second UI interval determines when this appears.
- A configured fan RPM maximum below 1 can no longer round down to a zero divisor.

## Checks

Commands run through the existing `.venv\Scripts\python.exe`:

- `-m unittest discover -s tests`: 244 passed, baseline 222.
- `-m compileall -q overlay.py setup.py tests tools/test_desktop_window_integration.py`.
- `setup.py --verify` and `setup.py --preflight`.
- `tools/test_desktop_window_integration.py`: real disposable off-screen HWNDs,
  DWM setter HRESULT=0, Z-order below an application, recovery of a minimized
  window, unchanged foreground; all created HWNDs are destroyed in finally.
- `git diff --check`.

Before the fixes, regressions reproduced taskbar triggering, stale animation
callbacks, malformed readings, persistent GPU/storage failure, and stale readings.
Separate tests of the new protections check the intended contract. No tests read
the clipboard, opened real sensors, changed autostart, or switched user windows.
The native smoke check does not test the real Explorer shell.

## Manual acceptance after a normal elevated launch

1. On the desktop, hover over the button to the right of the clock, then move the
   mouse away: the widget stays at its saved position without starting Peek.
   Repeat with the taskbar set to auto-hide.
2. Click Show Desktop, repeat while already on the desktop, and click once more.
   The widget should be visible without an extra click on the wallpaper.
3. From an application, trigger Peek at the edge; press Win+D during slide-in/out.
   The desktop position should be restored. Return to the application and repeat Peek.
4. Repeat with Peek OFF and Always on top ON/OFF; in fallback mode, check that the
   widget does not cover the application and sits acceptably relative to desktop icons.
5. After a normal resume/restart, check real CPU/GPU/RAM/storage readings.
   Check closing during animation and background recovery.

Exact shell acceptance, physical multi-monitor/mixed-DPI, and hot-plug remain
unconfirmed. The independent fallback cannot guarantee placement beneath Explorer's
child icon windows; this limitation is documented in README/AUDIT.
