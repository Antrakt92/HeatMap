# HeatMap: Show Desktop и надёжность показаний

Проверены desktop/Peek transitions, ошибки датчиков, фоновые повторы и свежесть
данных. Независимый агент повторно проверил реализацию и добавил sensor regressions.
DLL, driver, launcher, elevation и production autostart не менялись.

## Исправлено

- Правый край панели задач больше не активирует Peek. Учитываются work area,
  вложенные окна основной/вторичной панели и auto-hide shell surface. При правой
  панели задач trigger находится непосредственно слева от неё; межмониторные
  внутренние границы остаются исключены.
- Окно получает `DWMWA_EXCLUDED_FROM_PEEK`, чтобы системный desktop preview не
  делал его прозрачным. Microsoft описывает этот параметр как защиту от fading
  при Peek: [DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute).
- Независимый fallback восстанавливается после native minimize и поддерживает
  положение непосредственно перед поверхностью desktop в Z-order. Видимость
  проверяется каждые 250 мс, включая Peek OFF, без activation. Другие окна не
  перемещаются. Окно приложения перед desktop остаётся перед виджетом; topmost
  predecessor не превращает виджет в topmost. Используются документированные
  [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)
  и [ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow).
- При возврате на desktop активный Peek отменяется с восстановлением сохранённой
  позиции; учитывается оставшийся на панели задач focus. Старые callbacks
  анимации проверяют generation и не двигают окно новой сессии Peek.
- Некорректное числовое значение одного датчика больше не уничтожает допустимые
  значения того же hardware block. Обработаны `TypeError`, `ValueError`, overflow.
- Постоянный отказ hardware block запрашивает восстановление через существующий
  cooldown. Ошибка редкого storage update остаётся активной между cached samples;
  дисковые показания временно скрыты до настоящего refresh. При отказе одного диска
  это консервативно скрывает всю группу дисков; CPU/GPU продолжают обновляться.
- После 10 секунд без нового sample UI скрывает старые показания, показывает
  ожидание свежих данных и не обновляет peaks/alerts. Ровно 10 секунд ещё считаются
  допустимыми; период UI 2 секунды определяет фактический момент индикации.
- Fan RPM maximum в config не может округлиться из дроби меньше 1 в нулевой делитель.

## Проверки

Команды запускаются через существующий `.venv\Scripts\python.exe`:

- `-m unittest discover -s tests`: 244 passed, исходно 222.
- `-m compileall -q overlay.py setup.py tests tools/test_desktop_window_integration.py`.
- `setup.py --verify` и `setup.py --preflight`.
- `tools/test_desktop_window_integration.py`: реальные disposable off-screen HWND,
  DWM setter HRESULT=0, z-order ниже приложения, восстановление minimized window,
  foreground не изменён; все созданные HWND уничтожаются в finally.
- `git diff --check`.

Регрессии воспроизвели до исправления taskbar trigger, stale animation callback,
malformed readings, постоянный GPU/storage failure и устаревшие показания.
Отдельные тесты новых защит проверяют целевой контракт. Никакие тесты не читали
clipboard, не открывали реальные датчики, не меняли autostart и не переключали
пользовательские окна. Native smoke не является проверкой реального Explorer.

## Ручная acceptance после обычного elevated запуска

1. На desktop навести на кнопку справа от часов и убрать мышь: виджет остаётся
   на сохранённой позиции, не начинает Peek. Повторить при auto-hide taskbar.
2. Нажать Show Desktop, повторить на уже открытом desktop и нажать ещё раз.
   Виджет должен быть виден без дополнительного клика по обоям.
3. Из приложения вызвать Peek у края; во время slide-in/out нажать Win+D.
   Должна восстановиться desktop-позиция. Вернуться в приложение и повторить Peek.
4. Повторить с Peek OFF и Always on top ON/OFF; в fallback проверить отсутствие
   перекрытия приложения и приемлемое размещение относительно значков desktop.
5. После обычного resume/restart проверить реальные CPU/GPU/RAM/storage readings.
   Проверить close во время анимации и фонового восстановления.

Точная shell acceptance, physical multi-monitor/mixed-DPI и hot-plug остаются
неподтверждёнными. В независимом fallback нельзя гарантировать положение под
дочерними значками Explorer; это ограничение отражено в README/AUDIT.
