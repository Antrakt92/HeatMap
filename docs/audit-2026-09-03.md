# HeatMap: аудит запуска и фоновой работы

Дата: 2026-09-03. Проверены launcher/preflight, Task Scheduler, открытие и
восстановление LHM, WinAPI embedding, опрос Peek и существующие regression tests.

## Исправления

- Открытие LHM перенесено из конструктора окна в sensor worker. Tk может
  обрабатывать события, пока driver открывается; в это время виден статус прогрева.
- `Close`/`Open` больше не удерживают lock, который нужен потоку интерфейса.
- Неудачное восстановление с результатом `None` больше не отключает будущие
  попытки. Между завершением инициализации и следующей попыткой проходит минимум
  30 секунд, включая период прогрева с отсутствующими sensors.
- Worker закрывает собственный Computer при завершении; неудачный `Open` также
  выполняет best-effort cleanup частично созданного объекта. При зависшем native
  вызове и истечении пятисекундного shutdown timeout очистка не гарантирована:
  daemon thread может завершиться вместе с процессом.
- CPU baseline psutil инициализируется в том же потоке, который читает CPU load.
- CPU sanity check больше не вызывает Update у предшествующих GPU/storage blocks.
- Выходной буфер `SendMessageTimeoutW` имеет размер указателя вместо 32-битного
  DWORD. Контракт API задаёт `PDWORD_PTR`: [Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw).
- Опрос Peek прекращается при выключенном Peek и в режиме Always on top;
  переключение режима возобновляет один timer без дублирования callback chains.

Ранее подготовленное исправление RPC/CLIXML autostart сохранено и включено в
повторную полную проверку.

## Проверка производительности

- Синтетический прогрев с постоянно отсутствующими GPU sensors ранее вызывал
  20 повторных открытий за 40 модельных секунд. Новый regression подтверждает
  два открытия за 40 секунд, включая первое, с интервалом минимум 30 секунд.
- Неактивный Peek ранее продолжал 600 cursor polls в минуту. Теперь в этих
  режимах cursor polling и его timer отсутствуют; активный Peek сохраняет 100 ms.
- В hidden real-Tk smoke конструктор занял 0,058 секунды при намеренно
  заблокированном fake hardware Open. Callback Tk выполнился до разрешения Open;
  worker завершился и закрыл fake Computer ровно один раз.
- Отдельные локальные subprocess probes: import overlay 0,184 секунды,
  preflight 0,637 секунды. Это ориентиры до правок, а не показатели ускорения.

Это проверка конкретных путей и синтетических отказов. Полный Windows logon,
реальные sensor timings, CPU/RAM после перезапуска и cold-cache boot не измерялись.
30-секундная задержка задачи, UAC и DLL/dependency verification сохранены.
