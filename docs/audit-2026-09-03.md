# HeatMap: startup and background operation audit

Date: 2026-09-03. Reviewed the launcher/preflight, Task Scheduler, LHM opening and
recovery, WinAPI embedding, Peek polling, and existing regression tests.

## Fixes

- LHM opening moved from the window constructor into the sensor worker. Tk can
  process events while the driver opens; a warm-up status is displayed meanwhile.
- `Close`/`Open` no longer hold a lock needed by the UI thread.
- A failed recovery returning `None` no longer disables future attempts. At least
  30 seconds elapse between initialization completing and the next attempt,
  including warm-up periods with missing sensors.
- The worker closes its own Computer on exit; a failed `Open` also performs
  best-effort cleanup of the partially created object. If a native call hangs and
  the five-second shutdown timeout expires, cleanup is not guaranteed: the daemon
  thread may exit with the process.
- The psutil CPU baseline is initialized in the same thread that reads CPU load.
- The CPU sanity check no longer calls Update on preceding GPU/storage blocks.
- The `SendMessageTimeoutW` output buffer is pointer-sized instead of a 32-bit
  DWORD. The API contract specifies `PDWORD_PTR`: [Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw).
- Peek polling stops when Peek is disabled or Always on top is enabled;
  switching modes resumes a single timer without duplicating callback chains.

The previously prepared RPC/CLIXML autostart fix was retained and included in the
full verification rerun.

## Performance checks

- Synthetic warm-up with persistently missing GPU sensors previously caused
  20 reopenings over 40 simulated seconds. The new regression confirms two
  openings over 40 seconds, including the first, at least 30 seconds apart.
- Inactive Peek previously continued making 600 cursor polls per minute. These
  modes now have no cursor polling or timer; active Peek retains its 100 ms interval.
- In a hidden real-Tk smoke check, the constructor took 0.058 seconds while fake
  hardware Open was deliberately blocked. A Tk callback ran before Open was
  released; the worker exited and closed the fake Computer exactly once.
- Separate local subprocess probes: overlay import 0.184 seconds, preflight
  0.637 seconds. These are reference timings from before the changes, not speedup
  measurements.

These checks cover specific paths and synthetic failures. Full Windows logon,
real sensor timings, CPU/RAM after restart, and cold-cache boot were not measured.
The task's 30-second delay, UAC, and DLL/dependency verification were retained.
