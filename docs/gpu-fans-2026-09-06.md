# RX 7900 XT GPU fan control

User scope: control GPU cooling inside HeatMap, prefer stronger cooling over noise,
reach full airflow before Hotspot 100°C. CPU/GPU overclocking is outside this change.

Current startup/assistance behavior supersedes the initial always-controlled policy
below: [startup fan audit](startup-fan-audit-2026-09-06.md). Normal launches leave a
cool GPU driver-owned; only explicit commissioning runs the full-speed sweep.

## Policy and ownership

`Cooling → Automatic GPU fans` controls this Gigabyte RX 7900 XT only
(PCI vendor/device/subvendor/subsystem 1002/744C/1458/240C). New installations
default to OFF. The menu saves the requested enabled state. Normal launches report
standby until GPU-only intervention thresholds are met. The commissioning helper
with `--enable` saves `gpu_fans_enabled=true` only after verified control and restore.
The three temperature curves request speeds independently; the largest speed wins.

| Sensor | Temperature °C → speed % |
|---|---|
| Core | 40→30, 50→45, 60→65, 70→85, 75→100 |
| Hotspot | 50→30, 60→45, 75→70, 85→90, 90→100 |
| Memory | 55→30, 65→45, 75→65, 85→85, 90→100 |

Increases apply on the next two-second sample. Decreases wait ten seconds and
then proceed by at most two percentage points per second. All three temperatures
must exist before takeover. Missing/invalid temperatures after takeover request
100%; frozen metrics and missing/stopped tachometers produce an explicit failure
and restore the saved curve. Explicit commissioning checks 100% for fifteen seconds
against RPM; it is not part of normal startup.

`AUTO N%+` is a requested floor, not a measured duty or RPM percentage. The driver
curve retains a higher-temperature ramp to 100% at its own 90°C input, so a worker
crash does not leave a flat low-speed curve across all temperatures. The driver
may run fans faster than the requested floor. This fallback does not prove that
the driver's sensor equals Hotspot and cannot guarantee recovery from driver or
kernel hangs. The software policy explicitly reads Core, Hotspot and Memory.

The independent worker checks its owner PID/create time, heartbeat, singleton
mutex, temperature freshness, fan-curve readback and competing monitoring tools.
Closing HeatMap, switching GPU control OFF, or normal worker failure restores
the saved five-point curve and Zero RPM state, then verifies both. It does not
call whole-GPU factory reset or change clocks, voltage or power limits. A fan
setting changed externally stops the worker rather than repeatedly fighting it.
Force-killing the worker cannot run normal restoration; the last hardware curve
remains until the driver changes it or the next HeatMap GPU-worker launch recovers
the saved settings. An atomic `gpu-fan-status/recovery.json` journal records the
original curve before writes. Recovery requires the same adapter identity and a
recognized complete or partial HeatMap state; unfamiliar settings are preserved
and reported as a conflict. The journal is removed only after verified restoration.
Crash recovery is covered by simulated failures, not a forced live hardware kill.

## Runtime and source

`amd_gpu_fan.py` uses Python ctypes against the AMD driver's existing
`%SystemRoot%/System32/amdadlx64.dll`, loaded by absolute system path. Nothing is
downloaded or installed by this feature. Bundled LHM/PawnIO DLLs are unchanged.
The interface is opened only by the GPU worker; importing HeatMap or copying
diagnostics does not open another GPU controller.

ABI references: AMD's [ADLX SDK](https://github.com/GPUOpen-LibrariesAndSDKs/ADLX/tree/d9f04a9bba022d6cf6333f005dd540b4ad19fb63/SDK/Include),
`ISystem.h`, `IGPUTuning.h`, `IGPUManualFanTuning.h`, `IPerformanceMonitoring2.h`.
The 1.0 base ABI is initialized, and `IADLXGPUMetrics1` is queried explicitly.
The installed ADLX runtime is 1.5.0.124; Windows Authenticode verification returned
Valid (Microsoft Windows Hardware Compatibility Publisher). It was not replaced.
The C headers are reference material in the external source cache, not vendored.
ADL5 fan calls returned -1 and ADL8 calls -9 on this installed driver; those paths
are not used for writes. ADLX provides the three temperature readings and a
23–100% fan range on this card.
