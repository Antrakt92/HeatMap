# HeatMap — Desktop Hardware Monitor Overlay

Легковесный оверлей для Windows, который отображает температуры, нагрузку и состояние компонентов ПК прямо на рабочем столе — поверх обоев, но под иконками и окнами приложений.

## Что показывает

| Компонент | Метрики |
|-----------|---------|
| **CPU** | Температура, нагрузка (%), реальные RPM CPU Fan и CPU Optional Fan |
| **GPU** | Core, Hotspot и температура памяти отдельными строками, нагрузка (%), VRAM, вентилятор |
| **RAM** | Использование (%) |
| **Диски** | Температура, занятое место (%) — поддержка нескольких дисков |
| **Корпус** | RPM обнаруженных SYS-разъёмов, состояние автоматического управления |
| **Предупреждения** | Перегрев, большой Hotspot–Core, остановка ранее работавшего вентилятора под нагрузкой, заполнение памяти/дисков |

CPU/GPU/RAM обновляются каждые 2 секунды; storage sensors — примерно раз в 30 секунд, чтобы не создавать лишний I/O. Температуры и заполнение памяти/диска подсвечиваются цветом:
- **Зелёный** — ниже предупредительного порога
- **Жёлтый** — повышенное значение, стоит наблюдать
- **Красный** — достигнут порог действия и звукового предупреждения, если Alerts включены

Красный цвет не является доказательством повреждения или универсальной границей
безопасности оборудования. Это пороги приложения; точные аппаратные пределы зависят
от модели. Высокая загрузка CPU/GPU и скорость вентиляторов сами по себе не означают
перегрев: до 80% они зелёные, от 80% жёлтые, без красного состояния.

### Температуры и пороги

`G.CORE` — обычный датчик GPU Core/Edge. `HOTSPOT` — самая горячая точка кристалла
(junction), `V.TEMP` — температура видеопамяти. `VRAM` с процентом показывает её
заполнение. Все три температуры видны без включения Details. Если Core недоступен,
его строка показывает `--`, а не подменяет его Hotspot или памятью.
Алерт срабатывает по каждому датчику независимо: холодный Core не скрывает горячий
Hotspot. Details показывает разбивку температур и сохраняет отдельные пики Hotspot
и памяти до Reset peaks или перезапуска.

| Показатель | Жёлтый от | Красный / алерт от |
|------------|-----------|-------------------|
| CPU Package/Tctl/Tdie | 70°C | 85°C |
| GPU Core/Edge | 80°C | 90°C |
| GPU Hotspot/Junction | 90°C | 105°C |
| GPU Memory | 85°C | 100°C |
| Samsung 980 PRO / 860 EVO | 55°C | 70°C |
| Другие диски, консервативный общий порог | 45°C | 55°C |
| Заполнение RAM | 80% | 95% |
| Заполнение диска | 80% | 90% |

Пороги Core/Hotspot/Memory — отдельные предупредительные настройки приложения,
а не считанные из BIOS лимиты троттлинга. Не следует считать Hotspot 108–110°C
обычным зелёным состоянием только потому, что Core существенно холоднее.
Если это держится под нагрузкой, уменьшите нагрузку и проверьте охлаждение;
частоты и вентиляторы GPU остаются под управлением драйвера. Опциональное управление
корпусными вентиляторами описано ниже.

`HOT−CORE` постоянно показывает разницу температур. При Hotspot от 80°C разница
от 25°C жёлтая, от 35°C красная; текстовое предупреждение появляется после 10 секунд
непрерывного превышения. Это диагностическая эвристика, а не доказательство плохой
термопасты: сначала сопоставьте датчики и проверьте обдув.

`C.FAN`, `C.OPT`, `G.FAN` показывают измеренные RPM. Дополнительное `75% ctl` означает
считанную команду контроллера, а не процент от максимальных оборотов. Если контроллер
в автоматическом режиме не отдаёт процент, HeatMap не вычисляет его по случайному
наблюдавшемуся максимуму и не берёт его с другого разъёма. `0 RPM` — измеренный ноль,
`--` — нет измерения. SYS-строка появляется после обнаружения вращения и сохраняется,
если вентилятор затем остановится. `SYS 5/P` означает разъём с поддержкой помпы;
программа не определяет физическое место установки по номеру.

Для SSD основной `Temperature`/Composite имеет приоритет над `Temperature 2`.
Все дополнительные температуры доступны в Details → D.SENSE. Warning/Critical из
SMART не являются текущими измерениями и не выводятся как температура накопителя.
Если именованного основного датчика нет, используется самый горячий доступный.

Панель предупреждений видна и при выключенном звуке; тогда подписана `Sound: OFF`.
Для остановки вентилятора требуется ранее виденный положительный RPM, затем
10 секунд нуля при CPU от 70°C или Hotspot от 85°C. Неиспользуемый разъём с нулём
с первого чтения не считается неисправностью. Это обнаружение по тахометру,
а не гарантия физического вращения каждого вентилятора на разветвителе.

### Автоматический обдув корпуса

Профиль v1.0.0 предназначен только для **Gigabyte B550 AORUS PRO AC** с работающими
тахометрами **System Fan #1, #2, #4** и уже заданными **100% на SYS5/Pump и SYS6/Pump**.
Последние два разъёма делят дополнительный контроллер платы с SYS4, поэтому
неизвестная автоматическая кривая на них блокирует активацию. CPU/GPU и pump-разъёмы
не получают команд изменения скорости; SYS5/Pump сохраняет исходные 100%.
С другой платой или подключением HeatMap продолжает мониторинг, но отклоняет этот
профиль. Номера не означают «передний» или «задний» вентилятор.

После установки один раз запустите **`enable_case_fans.bat`** и подтвердите UAC.
Активация штатно закрывает предыдущий HeatMap из этого checkout, проверяет RPM на
100%, проверяет возврат прежнего управления, сохраняет настройку, включает звуковые
предупреждения и автозапуск, затем запускает обновлённый HeatMap. Ошибка проверки
не считается успешной настройкой. Результат находится в
`%LOCALAPPDATA%/HeatMap/activation-result.json`. Резервная копия конфигурации сохраняется
в той же папке перед изменением. В меню можно выключить `Automatic case fans`.

Для каждого компонента линейно интерполируется своя кривая; выбирается **максимальная
потребность в обдуве**, а не средняя температура:

| Датчик | Температура → команда корпусным вентиляторам |
|--------|--------------------------------------------|
| CPU | 40°C → 60%; 60°C → 70%; 75°C → 90%; 80°C → 100% |
| GPU Core | 40°C → 60%; 60°C → 80%; 75°C → 100% |
| GPU Hotspot | 60°C → 60%; 80°C → 80%; 95°C → 100% |
| GPU Memory | 60°C → 60%; 80°C → 80%; 95°C → 100% |

Большой горячий Hotspot–Core (от 35°C), отсутствие любого обязательного датчика или
потеря тахометра требуют 100%. Повышение немедленное при очередном опросе (обычно
2 секунды); снижение — после 15 секунд охлаждения, примерно по 2 процентных пункта
в секунду, с мёртвой зоной 3 пункта и минимумом 60%. Это консервативная настройка
этого профиля, а не универсальная формула для любых вентиляторов.

При каждом запуске первые 15 секунд отводятся проверке полного обдува. Нужны
подтверждение команды и рост RPM минимум на 8% относительно исходного значения
(если исходная команда уже не была 95–100%). Отсутствие отклика означает, что
подключение/режим требует проверки; программа не переключает PWM/DC вслепую.
`AIRFLOW: AUTO …%` появляется только после этой проверки.

Управление выполняет отдельный процесс с проверкой heartbeat окна и процесса-владельца.
При обычном закрытии, ошибке или пропаже heartbeat он возвращает исходное управление
через LHM и проверяет readback. Ошибка возврата выводится явно. Принудительное убийство
самого процесса управления, зависание native-драйвера или Windows не позволяют
гарантировать программный возврат: при таком сбое перезапустите Windows. Не запускайте
параллельно другой контроллер вентиляторов (FanControl, SIV, GCC, EasyTune).

Автозапуск из изменяемого checkout сохраняет обычный UAC при входе в Windows.
После запуска HeatMap профиль регулируется сам. Полностью бесшумный privileged
автозапуск требует отдельной защищённой установки, которой этот релиз не создаёт.

AMD также [разделяет Current и Junction Temperature в Adrenalin](https://www.amd.com/en/resources/support-articles/faqs/DH3-038.html).
Названия датчиков проверены по [исходникам используемой версии LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/30395c48a7f912894a7c392db8c11e1b97859658/LibreHardwareMonitorLib/Hardware/Gpu/AmdGpu.cs).
Для [980 PRO](https://download.semiconductor.samsung.com/resources/data-sheet/Samsung-NVMe-SSD-980-PRO-Data-Sheet_Rev.2.1_230509_10129500052824.pdf)
и [860 EVO](https://download.semiconductor.samsung.com/resources/data-sheet/Samsung_SSD_860_EVO_Data_Sheet_Rev1.pdf)
Samsung указывает рабочий диапазон 0–70°C. Это исключение не применяется ко всем
SSD/HDD; старый консервативный порог для неизвестных моделей сохранён.

Окно создаётся до открытия аппаратных датчиков и показывает статус прогрева.
Инициализация и восстановление датчиков выполняются в фоновом потоке, с паузой
не менее 30 секунд между повторными попытками. Когда Peek выключен или включён
режим «Поверх всех окон», частый опрос края экрана приостанавливается.

Если датчики перестают отдавать новые данные более 10 секунд, старые значения
заменяются на `--` и появляется `Sensors: waiting for fresh data`. На устаревших
данных алерты не повторяются; после нового замера показания возвращаются сами.
Постоянные ошибки отдельных устройств запускают восстановление с прежней паузой.
После ошибки обновления дисков их кэшированные показания скрыты до нового замера.

Некорректные значения датчиков не отображаются как реальные проценты или обороты.
Для CPU выбирается самая высокая допустимая температура из группы Package/Tctl/Tdie;
если таких датчиков нет, используется самая высокая доступная температура CPU.

## Возможности

- **Встраивание в рабочий стол** — виджет находится между обоями и иконками, не мешает работе
- **Перетаскивание** — зажмите заголовок и перетащите в удобное место
- **Система алертов** — звук при достижении красных порогов из таблицы выше; повтор не чаще раза в минуту, устаревшие данные не вызывают алерт
- **Автозапуск** — least-privilege задача стартует через 30 секунд после входа и показывает обычный UAC prompt перед доступом к sensors
- **Режим "Поверх всех окон"** — переключается через правый клик
- **Сохранение позиции** — запоминает расположение между запусками

Зона `Peek from edge` находится у правой границы рабочего пространства и не
включает панель задач или кнопку «Показать рабочий стол». На системах с правой
панелью задач используйте край непосредственно слева от неё. Системный Peek
Windows не должен делать виджет прозрачным. Отдельная проверка видимости работает
и при отключённом Peek, восстанавливая независимое окно после Show Desktop/Win+D
без захвата фокуса.

Если Explorer не предоставляет отдельный WorkerW для встраивания, используется
независимое окно непосредственно над поверхностью рабочего стола, ниже приложений.
В этом резервном режиме нет гарантии размещения под значками: выбирайте свободное
от значков место для виджета. Окно не привязывается к Progman, чтобы переживать
перезапуск Explorer.

## Установка

### Требования
- 64-bit Python 3.10+
- 64-bit Windows
- Права администратора (необходимы для чтения датчиков)

Проверенная среда: Python 3.13, pythonnet 3.1.0, psutil 7.2.2. Точные production versions закреплены в `constraints-known-good.txt`; отдельный CI lane проверяет новые допустимые версии.

### Шаги

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/Antrakt92/HeatMap.git
   cd HeatMap
   ```

2. **Создайте виртуальное окружение и установите зависимости:**
   ```bash
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt -c constraints-known-good.txt
   ```

3. **Проверьте библиотеки для мониторинга:**
   ```bash
   .venv\Scripts\python setup.py
   ```
   `setup.py` восстанавливает полный Windows runtime из точных NuGet assets,
   закреплённых в `runtime-lock.json`. До замены `lib/` он проверяет SHA-256
   каждого пакета, exact path/hash/size каждой DLL и весь staged runtime по
   `lib_manifest.json`; при ошибке сохраняется предыдущий рабочий runtime.
   Явный эквивалент команды — `python setup.py --restore-runtime`.
   Перед restore закройте запущенный HeatMap: Windows не позволяет атомарно
   заменить CLR DLL directory, пока процесс держит assemblies загруженными.

   Для CPU temperature и motherboard fan sensors также нужен PawnIO driver.
   Получите совместимый installer через проверяемый flow:
   ```bash
   .venv\Scripts\python setup.py --download-pawnio
   ```
   Setup фиксирует официальную версию, проверяет size, SHA-256, Authenticode
   publisher/certificate и только затем показывает путь к installer. Запустите
   этот файл от администратора и перезапустите Windows. Setup никогда не запускает
   driver installer автоматически.
   Если setup сообщает о pending installer operations, сначала перезапустите
   Windows, затем запускайте PawnIO installer; после установки нужен ещё один
   restart перед hardware smoke.

   После установки и перезапуска проверьте реальное открытие LHM и CPU sensor:
   ```bash
   .venv\Scripts\python setup.py --hardware-smoke
   ```
   Команда должна выполняться в elevated terminal и завершаться успешно только
   при наличии реального положительного CPU temperature reading.

   Чтобы только проверить уже существующий `lib/` без скачивания:
   ```bash
   .venv\Scripts\python setup.py --verify
   ```

4. **Запустите:**
   ```bash
   run_as_admin.bat
   ```
   Launcher проверяет кандидатов в порядке `.venv`, `venv`, затем все пары
   `python.exe`/`pythonw.exe` из `PATH` и выбирает первый интерпретатор, который
   полностью проходит CLR/LHM preflight. Preflight также сверяет установленные
   distributions с точными production versions из `constraints-known-good.txt`,
   поэтому новый пустой Python в начале `PATH` не блокирует рабочую среду и stale
   packages не принимаются как supported. Warning-only degraded state не блокирует
   UAC: текст сохраняется в `%LOCALAPPDATA%\HeatMap\last_preflight_warning.txt`, а
   состояние driver остаётся видимым внутри overlay.

   Или вручную от имени администратора:
   ```bash
   .venv\Scripts\python overlay.py
   ```

## Управление

| Действие | Как |
|----------|-----|
| Переместить | Зажать заголовок и перетащить |
| Контекстное меню | Правый клик по виджету |
| Поверх всех окон | ПКМ → "Always on top" |
| Автозапуск | ПКМ → "Autostart" |
| Алерты вкл/выкл | ПКМ → "Alerts" |
| Автоматика корпуса | `enable_case_fans.bat`; затем ПКМ → "Automatic case fans" |
| Peek с края | ПКМ → "Peek from edge" |
| Расширенные метрики | ПКМ → "Details" |
| Диагностика sensors | ПКМ → "Copy diagnostics" |
| Подготовить PawnIO repair | ПКМ → "Prepare verified PawnIO repair..." |
| Быстрый PawnIO repair | Нажать красную строку "Driver: install PawnIO" |
| Лог | ПКМ → "Open log file" / "Copy log path" |
| Сброс пиков | ПКМ → "Reset peaks" |
| Закрыть | Кнопка ✕ или ПКМ → "Close" |

`Copy diagnostics` собирает сведения в фоне. Пока отображается
`Collecting diagnostics...`, окно продолжает работать; по завершении результат
попадает в буфер обмена. Повторное нажатие не запускает ещё один сбор.

Результаты проверки запуска, датчиков и обработки ошибок описаны в
[дополнительном отчёте аудита](docs/audit-followup-2026-09-03.md).
Исправления Show Desktop, анимации и восстановления датчиков описаны в
[аудите от 5 сентября](docs/audit-2026-09-05.md).

### Безопасность автозапуска

Source checkout и его virtualenv изменяемы обычным пользователем, поэтому Task
Scheduler не должен исполнять их с `HighestAvailable` без нового consent. HeatMap
создаёт задачу с `LeastPrivilege`; она запускает обычный launcher, а elevation
происходит только через видимый UAC prompt. Старые небезопасные задачи мигрируются
через disable/verification/delete/re-create sequence. XML передаётся Task Scheduler
in-memory, без privileged чтения файла из пользовательского `%TEMP%`. Настраивать
автозапуск нужно той же Windows-учётной записью, которая открыла desktop session;
over-the-shoulder UAC с другими admin credentials отвергается. Checkout path с
символом `%` для Task Scheduler action не поддерживается, потому что `cmd.exe`
выполняет environment expansion. Silent autostart без UAC потребует отдельной
защищённой установки в admin-owned location и не имитируется ACL/hash-проверкой
checkout. Автоматический restart задачи намеренно отключён: для интерактивного UAC
launcher retry policy создавала бы повторяющиеся consent prompts.

## Технологии

- **Python** + **tkinter** — интерфейс
- **LibreHardwareMonitor** — чтение датчиков через .NET interop (pythonnet)
- **psutil** — дополнительные системные метрики
- **Windows API (ctypes)** — встраивание в рабочий стол

## Зачем нужны права администратора?

LibreHardwareMonitor требует прямой доступ к аппаратным датчикам для чтения температур, напряжений и оборотов вентиляторов. Без прав администратора эти данные недоступны.
